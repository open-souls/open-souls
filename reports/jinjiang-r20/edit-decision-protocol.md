# 编辑判断协议

配合 `jinjiang-rubric.md` 使用。本协议只回答“该不该改”，不代替作者完成改写。

## 0. 一句话规则

写之前先答：本章谁要什么，谁阻止，付出什么代价？

如果答不上来，先补背景；如果代价是空，本章就该删或重构。

## 1. 写作前五问

1. POV 角色是谁？本章核心欲是什么？
2. 谁挡在中间？是人、证据还是时间？
3. 阻力具体到什么程度？读者能否复述？
4. POV 角色最后做了什么动作或决定？
5. 章尾读者必须问的下个问题是什么？

答不出第五问，重写末段。

## 2. 写作后五问

1. 首段是否出现动作与阻力，而不是先写景？
2. 中段是否至少有一次 POV 角色的选择？
3. 章尾是否停在动作前、新证据或未答问题？
4. 关系或信息是否真的改变？没有就重写。
5. 是否删除同义重复句，而不是只换词？

## 3. 改稿顺序

1. 短章：补选择、阻力、代价或新信息，不补空景物。
2. 章尾弱：补下章必答的具体问题，不补泛化隐喻。
3. 句子重复：删除整句，不做同义替换。
4. 填充描写：删除整段，不要软化。
5. 开句同构：重做首句结构，不要扰动中段。
6. 编辑标记或公式回环：重写整章，不做局部遮盖。

## 4. 常见借口不通过

- “我已经写了”：重写或重写末段。
- “留给下一章”：本章仍须提供具体钩子。
- “这是文学笔法”：文学笔法也要改变人物、信息或关系。
- “读者会理解”：读者不欠作者理解。
- “工程分是 9.8”：工程分不是市场分。

## 5. 改稿后同步

- 重跑 `engine\prose_lint.py --include-stubs`。
- 重跑 `tools\chapter_by_chapter_audit.py`。
- 同步 `blow-up-playbook.md` 和 `per-chapter-gap.md` 的数字。
- 禁止只跑 lint 不重跑 audit。

# 《镇狱之渊》晋江化评估架构

目标不是制造一个“爆款分数”，而是建立一个不会自我欺骗的改稿系统。

## 总流程

```text
平台事实
    ↓
全文正文与元数据
    ↓
确定性审计
    ↓
编辑五问与 rubric
    ↓
小批量改稿
    ↓
真人盲读
    ↓
只把重复出现的问题升级为结构任务
```

## 五层架构

### 第一层：平台事实

文件：`research-notes.md`

只记录晋江官方公开页面能证明的内容，例如收藏、VIP、营养液、霸王票、榜单与合规规则。平台没有公开“高分文笔公式”，所以不能把行业传言写成平台标准。

### 第二层：全书证据

文件：`chapter-by-chapter-audit.json`、`chapter-by-chapter-audit.md`

输入是 `chronicle` 中当前第 1 至 1145 回的正文。审计负责发现短章、重复句、填充描写、开句同构与章尾弱信号，不负责判断文学价值。

### 第三层：编辑决策

文件：`jinjiang-rubric.md`、`edit-decision-protocol.md`、`rubric-scoreboard.md`

每章必须回答：

1. POV 角色要什么？
2. 谁或什么阻止？
3. 代价是什么？
4. 下章必须追看的具体问题是什么？
5. 本章是否改变了下章开局位置？

第三问是硬门槛。只加线索、不加代价，不算推进。

### 第四层：读者验证

文件：`reader-blindtest-protocol.md`、`blindtest_packs/`

工程分只说明代码能复现规则。真人盲读才提供弃读点、关系偏好、追问内容与 50 章留存意愿。两者独立，取最低；没有真人数据时不使用“上瘾”“爆款”“读者会追更”。

### 第五层：改稿循环

```text
审计 → 排序 → 单章写五问 → 改一个因果单元 → lint → audit → 读者包
```

单次只改一个因果单元，优先级如下：

1. 短章，补选择、阻力、代价或新信息。
2. 章尾弱，补具体未完成动作或必须回答的问题。
3. 句子重复，删除整句。
4. 填充描写，删除整段。
5. 关系只换观察者，补一次主动承担后果。

## 固定命令

```powershell
py -3 -X utf8 engine\prose_lint.py --include-stubs
py -3 -X utf8 tools\chapter_by_chapter_audit.py
py -3 -X utf8 tools\jinjiang_rubric.py
py -3 -X utf8 tools\reader_blindtest_pack.py
```

## 禁止越级

- 不能用 `avg_binge_score` 宣称读者上瘾。
- 不能把 `hook_signal` 当成人类悬念判断。
- 不能先改数字，再倒推正文变好。
- 不能用自写 `review` 或 `score` 代替读者反馈。
- 不能用一次读者意见判定全书结构问题。
- 不能在没有最新 audit 的情况下更新报告基线。

## 当前状态

截至 2026-09-04，本架构已经生成并跑通。当前正文工程信号为 0 个 lint ERROR、12 个 WARN、526 回章尾弱、89 回句子重复、34 回填充描写、1 回开句同构。工程 rubric 平均 6.31/10，章尾弱占比 45.9%。这不是市场成绩，也不是晋江高分结论。
